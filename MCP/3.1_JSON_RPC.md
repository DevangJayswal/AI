## What is JSON-RPC?

**JSON-RPC** is a stateless, lightweight remote procedure call (RPC) protocol that uses JSON to encode messages between clients and servers[1][2][3]. It allows a client to invoke methods on a remote server as if they were local function calls, making it a simple and efficient way to enable communication between distributed systems[3][4].

---

### **Key Features**

- **Stateless:** Each request is independent; the server does not retain session information between requests[1][3].
- **Lightweight:** Minimal overhead, using plain JSON for both requests and responses[1][3].
- **Transport Agnostic:** Can operate over HTTP, WebSockets, TCP, or any other transport mechanism[2][5].
- **Method-Oriented:** Focuses on calling named methods with parameters, rather than manipulating resources via URLs as in REST[3][4].

---

### **How JSON-RPC Works**

#### **Request Structure**

A JSON-RPC request is a JSON object with the following fields[1][6][4]:

- `"jsonrpc"`: The protocol version, always `"2.0"` for JSON-RPC 2.0.
- `"method"`: The name of the method to invoke.
- `"params"`: (Optional) Array or object containing parameters for the method.
- `"id"`: A unique identifier to match requests with responses.

**Example:**
```json
{
  "jsonrpc": "2.0",
  "method": "subtract",
  "params": [42, 23],
  "id": 1
}
```

#### **Response Structure**

The server replies with a JSON object containing[1][6][4]:

- `"jsonrpc"`: The protocol version.
- `"result"`: The result of the method call (if successful).
- `"error"`: (Optional) An error object if the call failed.
- `"id"`: The same identifier as in the request.

**Example (Success):**
```json
{
  "jsonrpc": "2.0",
  "result": 19,
  "id": 1
}
```

**Example (Error):**
```json
{
  "jsonrpc": "2.0",
  "error": {
    "code": -32601,
    "message": "Method not found"
  },
  "id": 1
}
```

#### **Notifications**

If the client sends a request without an `"id"` field, it is considered a *notification* and does not require a response from the server[1][2].

---

### **Comparison to REST**

- **REST** is resource-oriented (using URLs and HTTP verbs), while **JSON-RPC** is method-oriented (invoking named procedures)[3].
- **JSON-RPC** uses a consistent message format for all operations, whereas REST endpoints and payloads can vary widely[3].
- **JSON-RPC** can be more efficient for certain use cases, especially when you want to call remote functions directly without mapping to resources[3].

---

### **Use Cases**

- Blockchain node communication (e.g., Ethereum, Bitcoin)
- Distributed systems needing remote function invocation
- AI and agentic systems (e.g., MCP servers)

---

**In summary:**  
JSON-RPC is a simple, standardized protocol for remote method invocation using JSON messages, making it ideal for scenarios where lightweight, stateless, and transport-agnostic communication is required[1][2][3].
